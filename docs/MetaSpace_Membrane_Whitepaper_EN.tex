\titleband{MetaSpace Membrane}{Deterministic Containment for Machine-Generated Software}{An undecidable question turned into a decidable one, and the answer enforced deny-by-default.}

\sect{Abstract}
Machine-generated software cannot be verified for \emph{intent}: by Rice's theorem, whether an
arbitrary program conforms to its author's intent is undecidable. MetaSpace Membrane replaces
verification of intent with \emph{containment of effect}. A program's effects are constrained to
a boundary declared in a single, deliberately Turing-incomplete \code{.bio} constitution, and any
effect outside the boundary is deterministically refused. Containment reduces to \emph{set
membership}, which is decidable, so the runtime decision is deterministic and reproducible. We
describe three composable membranes (capability, value-invariant, epistemic), a provenance chain
(synthesis $\to$ human ratification $\to$ production gate), a productized surface (a \code{metaspace}
CLI, an agent-membrane ``Warden'' proven end-to-end, a second harness via a generic MCP broker over
one shared decision core, and a Linux Landlock OS-sandbox that confines stock native binaries), and
an evidence ledger of \textbf{twenty-one} reproducible proofs run by a single command. We are
explicit about what is \emph{hard} (unbypassable under the WebAssembly capability model, or
kernel-enforced under Landlock) and what is \emph{soft} (semantic faithfulness, non-deterministic
and non-enforcing).

\sect{1.\quad Problem --- intent is undecidable}
The correctness question --- \emph{does the program do what its author intended?} --- is
undecidable: Rice's theorem states that every non-trivial semantic property of programs is
undecidable. For machine-generated code the gap is acute: the generator's intent is not
mechanically checkable, and a plausible-looking program may take effects its author never
sanctioned --- deleting files, exfiltrating data, or acting on invented facts. Verifying
\emph{correctness} therefore does not scale to this setting.

\sect{2.\quad Approach --- containment, not correctness}
We substitute a decidable question. Instead of \emph{``is the program right?''} we ask
\emph{``is the program's effect inside the declared boundary?''} --- a set-membership test, which
is decidable and deterministic. The boundary is a \code{.bio} constitution, deliberately
Turing-incomplete, so the policy is finite and analyzable. A ``bug'' is redefined as \emph{a
deviation from the constitution}: machine-measurable and enforceable. \arch

\sect{3.\quad Architecture --- one pattern, three membranes}
All three membranes are the same reference-monitor pattern at a chokepoint,
\textbf{deny-by-default}, with the decision made by the constitution.
\begin{itemize}
\item \textbf{Capability membrane} --- mediates effects on the world (filesystem, network, subprocess, \ldots).
\item \textbf{Value-invariant membrane} --- guards declared safety bounds (numeric ranges; in this
repository realized as the hard tier's schema \code{RANGE} check, proven in \code{run\_knowledge\_demo}).
\item \textbf{Epistemic membrane} --- bounds factual assertion and knowledge-based actuation.
\end{itemize}
\noindent\textbf{Guarantee ladder.} A membrane is only as hard as its chokepoint is unbypassable:
heuristic (advisory) $<$ language-level (bypassable via \code{ctypes}/syscalls) $<$ harness-level
(hard for the agent, since it sits outside it) $<$ WebAssembly (unbypassable: a guest has no
ambient authority). \arch\\
\noindent\textbf{Composition.} The epistemic membrane alone is only advisory --- an app may
simply not call it. It becomes hard \emph{behind} the capability membrane, which guarantees the
sole path to the world is a mediated gate. The three compose in defence-in-depth. \arch

\sect{4.\quad Provenance chain --- synthesis, ratification, gate}
\begin{itemize}
\item \textbf{Synthesis.} Static analysis of code drafts a constitution, marked
\textsc{synthesized}. This is a name-based heuristic, not a guarantee. \arch
\item \textbf{Ratification.} A human reviews and stamps it \textsc{ratified}. The stamp is
\emph{content-bound}: it carries a fingerprint of the enforced policy, so a later edit that widens
a scope or adds a capability reads as \textsc{tampered}. \measured
\item \textbf{Gate.} In production, only a \textsc{ratified} constitution runs; a \textsc{synthesized}
or \textsc{tampered} one is refused, fail-closed. A policy is enforceable only after human
ratification, and cannot be broadened afterwards without detection. \measured
\end{itemize}

\sect{6.\quad Scope, trust boundary \& honest limits}
\begin{itemize}
\item The \emph{hard} guarantee holds under a real substrate: the WebAssembly capability model, or a
Linux \textbf{Landlock} OS-sandbox (\code{sandbox\_enforcer.py}, pure-Python \code{ctypes}) that
confines a stock native program's filesystem \emph{writes} to its \code{.bio} from the kernel
(out-of-scope write $\to$ \code{EACCES}; read/execute unrestricted so any binary runs; Linux-only;
fail-closed if unavailable). A language-level guard is bypassable (\code{ctypes}, direct syscalls)
and is therefore \emph{not} shipped as a product.
\item The membrane's decision is factored into one harness-independent core; the Claude Code hook
and a generic \textbf{MCP capability-broker} are thin adapters over it and reach identical verdicts
(\code{run\_mcp\_e2e}). An MCP tool the agent may \emph{voluntarily} call is only advisory; the
broker is \emph{hard} only when the agent's ambient authority is removed so its tools are the sole
path to effects.
\item Constitution synthesis is a static, name-based heuristic; it can under-declare under heavy
dynamism. A \textbf{dry-run learning mode} observes concrete runtime effects and augments the
constitution \emph{before} ratification, so an incomplete policy does not false-positive-block
legitimate behaviour. The runtime membrane --- not the synthesis --- remains the guarantee.
\item The epistemic \emph{soft} tier (semantic faithfulness) is non-deterministic and does not
enforce; it is an \textbf{advisory flag}, not a membrane --- it \emph{qualifies} (flags), never
\emph{contains} (blocks). A reproducible threat-model matrix shows honestly that a schema-valid but
fabricated statement passes the hard layers and is only flagged. Its backends are a dependency-free
heuristic and an optional LLM judge.
\item The agent membrane mediates tool \emph{effects}, not the model's prose; its shell check is a
\textbf{structural allowlist} (a shell lexer resolving real program names) --- obfuscation-resistant
and fail-closed.
\item \textbf{TCB:} the host runtime (\code{wasmtime}), the operating system (including the Linux
kernel's Landlock LSM for the OS-sandbox path), and the Python interpreter hosting the membrane are
assumed intact. WASI filesystem granularity is at the directory/permission level.
\item This artifact does \emph{not} use SMT/Z3 proof or hardware synthesis; those belong to the
broader MetaSpace.Bio programme and are out of scope here. No figure above is a benchmark or a
marketing number: every \measured\ item is a reproducible run.
\item The structural shell policy, the dry-run learning mode, the threat-model matrix, the
ratification cognitive brake and the full per-kind capability mediation were added in response to
two rounds of external technical review; each ships with its own reproducible proof.
\end{itemize}
